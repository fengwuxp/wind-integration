# 指标模型与整体流程

“客户 C-17 在 9 月的美元卡交易授权通过率是多少？”要回答它，先按授权发生时间统计总笔数和批准笔数，再用批准笔数除以总笔数。如果历史计数已经保存，本次查询还可以只读其后的交易明细。选用哪条取数路线，由宿主应用依据指标修订和已提交数据决定。

## 从业务问题到指标模型

| 概念 | 本例中的含义 | 何时确定 |
| --- | --- | --- |
| 指标定义 | 总笔数、批准笔数各自从交易事实取数，属于 RAW。通过率引用这两个计数的精确修订，属于 DERIVED | 定义并发布口径时 |
| 主体、维度和窗口 | 主体类型为客户，维度为币种，统计时间取授权时间。调用方给出客户 C-17、USD 和 9 月的半开时间范围 | 类型与字段写入定义，具体取值随请求传入 |
| 原始量与最终值 | 两个计数可以跨连续时段相加。分子和分母分别汇总后，才计算目标范围的通过率 | 计数在取数时产生，比率在求值时产生 |
| 物化计划 | 将需要保存的精确 RAW 修订归入同一计划，约定业务键来源、完整保存目标和时间规则 | 准备快照路线时 |
| 快照与水位 | 某个客户、币种、目标版本实际持久化的状态及其覆盖。水位给出下一次增量读取的起点 | 完整保存成功时 |

指标定义使用 schema 6，物化计划使用 schema 4。schemaVersion 标识存储协议格式。业务修订标识具体统计口径，例如“授权总笔数第 1 版”。派生定义固定其直接依赖的修订，宿主保存、发布并检查依赖可读性。这样即使总笔数日后改变口径，历史通过率仍能说明当时采用哪一版。

## 一次查询与一次物化如何配合

1. **定义与发布。** 业务方确定主体、时间字段、维度、统计规则和空值含义。宿主映射真实事实源，检查依赖并选出生效修订。只用实时数据的指标完成这些步骤即可查询。
2. **生成历史快照。** 宿主调度物化任务，枚举计划的完整业务键，读取上次已提交状态。按键查询新增区间的原始量并合并，在同一保存组内提交值、覆盖及版本。
3. **执行查询。** 业务入口校验访问资格。查询服务在同一读取视图内固定定义、精确依赖及各来源的读取路线。实时路线访问事实，快照路线读取已提交记录，分段路线按连续覆盖衔接历史快照和实时部分。
4. **交付结果。** 对每个 RAW 来源核对实际范围、合并原始量，再按依赖和表达式计算最终值。调用方取得实际定义修订、值和覆盖范围，可以把多个指标组装成报表对象。

Wind 提供版本化模型、查询和仓储契约、参数化 SQL 生成、表达式求值与数值归一化。实时仓储按已选 RAW 修订和查询条件返回完整统计字段或 SQL 结果列，快照仓储按业务键读写累计对象及覆盖区间。接入应用负责数据源、权限、生效版本、调度、事务和并发写入。查询消费已提交数据，物化任务成功提交后才推进水位。这两条路径可以独立运行。

- 从一个最小计数定义开始，完成一次实时查询并选择正式读取入口。[指标定义与查询](defining-and-querying.md)
- 把历史计数与实时计数合成通过率，然后保存下一版累计状态。[计算与结果处理](calculation-and-results.md)

公共模块使用 JDK 25。可在仓库根目录运行 `mvn -pl wind-metrics -am test -Dmaven.test.skip=false -DskipTests=false -Dtest.ignore.failure=false -Dmaven.test.failure.ignore=false`，从 Surefire 报告核对模型、计算及公共契约。宿主接入另行验证真实字段映射、查询隔离和保存事务。
